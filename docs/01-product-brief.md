# 个人待办管理工具：产品简报

> 文档状态：MVP 基线 + Phase 5 已批准范围
> 产品形态：响应式 Web 应用 / PWA
> 使用对象：单一用户、个人使用
> 数据策略：本地优先；无需登录可本地使用；登录后可选私有云同步

## 1. 一句话定义

一个打开即用、本地优先的个人待办工具，帮助用户在 10 秒内收集任务，并明确区分“今天计划做什么”和“最晚何时必须完成”；需要跨浏览器或设备时，可登录启用私有云同步。

## 2. 问题背景

个人任务常分散在聊天、便签、日历和脑海中。现有工具常见两种问题：

- 功能过多，记录一项任务需要面对大量字段和配置。
- 只围绕截止日期组织任务，导致 Today 充满逾期事项，用户无法表达自己今天真正准备做什么。

本产品优先解决“快速收集”和“每日聚焦”，而不是构建完整项目管理系统。

## 3. 目标用户

### 3.1 核心用户

- 同时管理工作和生活事项的个人用户。
- 希望使用电脑与手机浏览器记录任务。
- 不希望为了个人待办创建团队空间或配置复杂数据库。
- 关注数据隐私，希望任务默认保存在自己的设备中。

### 3.2 典型场景

- 会议中快速记下一项跟进任务。
- 每天早上从收集箱和未来任务中安排今日事项。
- 区分“今天准备写方案”和“周五必须提交方案”。
- 查看未来几天是否安排过载。
- 按工作、生活、等待回复等维度查找任务。
- 导出全部数据作为备份或迁移文件。

## 4. 用户核心任务（Jobs to Be Done）

1. 当我突然想到一件事时，我希望立即记下来，以免打断当前工作。
2. 当我开始一天时，我希望看到今天真正打算完成的事项，而不是一长串无差别任务。
3. 当某项任务有硬性期限时，我希望它能与我的计划日期同时存在。
4. 当任务越来越多时，我希望按项目、标签、重要性、紧急性、时间和关键词快速找到它。
5. 当我完成或误操作任务时，我希望状态变化清楚并且可以撤销。
6. 当我担心数据丢失时，我希望能随时导出并验证恢复。
7. 当我更换浏览器、访问域名或设备时，我希望登录后看到同一份任务，而不是依赖某个浏览器源下的本地数据。

## 5. 产品原则

### P-01 快速收集

创建任务只强制要求标题；其他字段不阻塞记录。

### P-02 今日计划与截止日期分离

`plannedDate` 表示准备哪天处理，`deadline` 表示最晚完成日期。界面不把两者混成一个“日期”。

### P-03 默认简单，按需展开

列表只展示完成状态、标题和关键元信息；备注、项目、标签等在详情中编辑。

### P-04 一份任务，多个视图

Inbox、Today、Upcoming、项目、标签和 Completed 都由同一份任务数据动态计算。

### P-05 本地优先与数据可携带

无账号也能完成全部本地操作；数据先写入本地数据库。用户可导出版本化 JSON，也可主动登录启用私有云同步。

### P-06 可撤销优先

完成、删除等高频操作提供即时反馈和撤销，减少确认弹窗。

### P-07 先可用，再智能

不以 AI、自然语言、自动建议作为 MVP 可用性的前提。

### P-08 重要性与紧急性独立

“重要/不重要”和“紧急/不紧急”不是四个可同时勾选的普通标签，而是两个互斥维度。两者可以组合成四象限，并保留“未分类”状态以避免快速创建时被迫判断。

## 6. MVP 目标

- 完成任务创建、编辑、计划、截止、完成、恢复和删除闭环。
- 提供 Inbox、Today、Upcoming、Projects、Tags、Completed 视图。
- 支持设置重要性与紧急性，并按单一维度、四象限或未分类状态筛选。
- 支持搜索、基础筛选和排序。
- 在刷新、关闭浏览器和离线后保留数据。
- 支持完整导出、校验和恢复。
- 在桌面和常见手机宽度下可用。

## 7. 非目标

MVP 基线不包含：

- 团队成员、任务分派、评论和共享。
- 登录、云同步和多设备冲突解决；这些能力已进入独立的 Phase 5 范围，不追溯改写 MVP 完成定义。
- 邮件、日历或聊天软件集成。
- 周期任务。
- 系统通知和位置提醒。
- 自然语言日期解析。
- AI 拆解、AI 排期或自动判断重要性/紧急性。
- 习惯追踪、番茄钟、统计报表。
- 附件、富文本编辑和复杂子任务依赖。
- 看板、甘特图和完整日历视图。

## 8. 成功指标

### 8.1 可用性指标

- 从打开应用到创建纯标题任务，熟练用户不超过 10 秒。
- 快速创建流程只需要输入标题并确认。
- 用户能在不阅读帮助文档的情况下识别 Inbox、Today 和 Upcoming。
- 完成、恢复、删除和撤销均有明确反馈。

### 8.2 可靠性指标

- 页面刷新和浏览器重启后数据保持一致。
- 离线状态下可创建、编辑和完成任务。
- 有效导出文件可以恢复任务、项目、标签、重要性/紧急性分类和设置。
- 无效导入文件不会部分写入或破坏现有数据。

### 8.3 Phase 5 同步指标

- 登录用户在两个受支持浏览器或设备中最终看到一致的任务、项目、标签和设置。
- 离线修改先可靠保存在本地；恢复网络后可以重试并同步，不出现“显示已同步但云端没有数据”的假成功。
- 首次上传本地数据前展示摘要并取得确认；迁移失败不清除本地数据。
- 并发冲突不得静默覆盖用户修改；冲突内容可查看并由用户选择保留版本。
- 未登录用户和未启用同步的数据不上传服务器。

### 8.4 工程质量指标

- P0 需求均有自动化或明确人工验收用例。
- 关键业务规则有单元测试。
- 创建、今日计划、完成、恢复、导出、导入有端到端覆盖。
- 类型检查、单元测试和生产构建全部通过后才视为可发布。

## 9. MVP 使用闭环

```text
想到任务
  → 快速写入 Inbox
  → 稍后补充项目、标签、重要性、紧急性、计划日期或截止日期
  → 在 Today 决定当天行动
  → 标记完成
  → 在 Completed 中可追溯
  → 定期导出备份
```

## 10. 发布边界

满足以下条件才能称为 MVP：

1. [`02-mvp-requirements.md`](./02-mvp-requirements.md) 中所有 P0 需求验收通过。
2. [`06-acceptance-tests.md`](./06-acceptance-tests.md) 中阻断级场景全部通过。
3. 真实浏览器完成一次“创建数据 → 导出 → 清空测试环境 → 导入恢复”的演练。
4. 在至少一个桌面浏览器和一个移动端尺寸完成核心流程测试。

## 11. 已批准的 Phase 5：私有云持久化

Phase 5 在不破坏本地优先体验的前提下，解决 IndexedDB 被浏览器、端口、域名和设备隔离导致的“历史记录像是消失”的问题。

范围包含：

- 可选的单用户登录；登录只用于识别用户和保护云端数据。
- 托管 PostgreSQL 与仅服务端可访问的数据库凭据。
- 通过受鉴权的 API 同步任务、项目、标签和设置。
- 本地事务 + 待同步队列，支持离线编辑和联网后重试。
- 首次登录时把现有 IndexedDB 数据安全迁移到空的云端账户。
- 多设备并发版本检查、删除墓碑和可见的冲突处理。
- 保留 JSON 导出/恢复作为独立备份手段。

明确不包含：团队协作、共享清单、任务分派、端到端加密、实时多人编辑，以及用同步替代用户可下载的备份。

## 12. 后续路线假设

- V1.1：子任务、拖拽排序、自然语言日期、快捷键增强。
- V1.2：周期任务、提醒和日历视图。
- Phase 5：可选账号、私有云同步和多设备冲突保护（已批准，按 `SYNC-001`～`SYNC-006` 分阶段实施）。
- 后续候选：端到端加密、共享清单和团队协作；均需另行批准范围。

除已批准的 Phase 5 外，路线只表示可能方向，进入开发前仍需单独确认。
