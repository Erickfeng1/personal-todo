# MVP 与单用户云端版验收测试

> 文档状态：MVP 功能基线 + Phase 5 单用户云端版已批准范围
> 目的：把需求转为可执行的验收场景
> 级别：Blocker = 对应阶段发布阻断；Major = 应在对应阶段发布前通过；Minor = 可记录后修复

## 1. 验收环境

- 桌面：至少一个 Chromium 浏览器，并抽测 Safari 或 Firefox。
- 移动端：360px 宽度视口，必要时补充真实手机浏览器。
- 时区：至少测试 `Asia/Shanghai`，日期工具单测覆盖另一个有夏令时的时区。
- 数据集：空库、小数据集、5,000 条压力数据集。
- 离线测试：验证应用壳可打开、业务写入明确不可用且不会显示假成功。
- Phase 5：隔离的测试密码/会话密钥、测试 PostgreSQL、两个不同浏览器上下文；不得使用生产数据库。

## 2. 发布阻断条件

以下任一发生即不能发布：

- 创建或编辑后刷新导致数据丢失。
- Today 错把计划日期当成截止日期，或修改计划日期时清除了截止日期。
- 导入失败后现有数据被部分清除。
- 删除标签导致任务被删除。
- 完成/恢复状态与 Completed 不一致。
- 同一任务可以同时选择“重要”和“不重要”，或同时选择“紧急”和“不紧急”。
- 核心操作在 360px 宽度无法完成。
- 离线或服务端失败时界面显示保存成功。
- 未经首次迁移确认就上传旧 IndexedDB 任务内容。
- 未建立有效密码会话仍能读取或修改业务实体。
- 云端写入失败时客户端内存被更新为未持久化的新值。
- 并发修改、删除或恢复导致某一版本被静默覆盖。
- 首次迁移失败导致 IndexedDB 原数据丢失或 Neon 留下部分数据。
- Preview 环境连接 Production 数据库。

## 3. 功能验收场景

### AC-001 快速创建普通任务

- 关联需求：MVP-001、MVP-005
- 级别：Blocker

```gherkin
假如 Inbox 为空
当我输入“提交周报”并按 Enter
那么列表立即出现“提交周报”
并且任务处于未完成状态
并且任务位于 Inbox
并且重要性和紧急性均为“未设置”
并且输入框被清空且保持可继续输入
```

### AC-002 拒绝空标题

- 级别：Major

```gherkin
假如当前设备已启用同步

那么系统要求先暂停同步并展示恢复与云端的关系
并且恢复不会绕过 revision 检查直接覆盖云端
并且只有我再次明确确认后才把恢复结果作为新变更排队上传
```

### AC-046 未解锁时阻止业务访问

- 关联需求：CLOUD-001、NFR-CLOUD-001
- 级别：Blocker

```gherkin
假如浏览器没有有效会话
当我打开应用或直接请求任一业务 API
那么页面只显示访问密码入口
并且业务 API 返回 401
并且任务标题、数量和正文均未返回
```

### AC-047 密码会话安全

- 关联需求：CLOUD-001、NFR-CLOUD-001
- 级别：Blocker

```gherkin
假如服务端已配置有效的 scrypt 密码哈希和独立会话密钥
当我输入正确密码
那么响应建立 HttpOnly、SameSite=Strict 的短期 Cookie
并且生产环境 Cookie 带 Secure
并且密码、哈希和签名密钥不出现在客户端构建、响应正文或日志
```

### AC-048 云端写入与刷新保留

- 关联需求：CLOUD-002、MVP-001、MVP-002
- 级别：Blocker

```gherkin
假如我已解锁应用
当我创建并编辑任务且 API 返回成功
然后刷新页面或在第二个浏览器解锁
那么两处从 Neon 读取到相同任务和字段
并且 IndexedDB 没有新增该业务记录
```

### AC-049 写入失败不假成功

- 关联需求：CLOUD-002、NFR-002
- 级别：Blocker

```gherkin
假如当前页面显示云端旧值
当网络、校验或数据库写入失败
那么页面保留旧值并展示可重试错误
并且刷新后仍读取旧的云端值
```

### AC-050 过期 revision 不静默覆盖

- 关联需求：CLOUD-002
- 级别：Blocker

```gherkin
假如两个浏览器基于同一 revision 编辑同一实体
当第一个写入成功后第二个再提交旧 revision
那么第二个请求返回 409
并且第一个版本仍保存在 Neon
并且第二个页面重新加载并提示记录已更新
```

### AC-051 一次性迁移到空云端

- 关联需求：CLOUD-003
- 级别：Blocker

```gherkin
假如旧 IndexedDB 有数据且 Neon 业务数据为空
当我查看摘要并确认迁移
那么服务端在一个事务中导入所有任务、项目、标签和设置
并且页面从 Neon 重新加载相同数量
并且旧 IndexedDB 数据仍保留
```

### AC-052 非空云端阻止旧数据覆盖

- 关联需求：CLOUD-003
- 级别：Blocker

```gherkin
假如 Neon 已有任一业务实体
当浏览器检测到旧 IndexedDB 数据
那么系统不提供直接覆盖导入
并且引导先导出云端备份
```

### AC-053 云端导出与事务恢复

- 关联需求：CLOUD-002、MVP-011
- 级别：Blocker

```gherkin
假如我已解锁并导出备份
当我确认使用有效文件替换恢复
那么文件来自当前云端快照
并且服务端在一个 Neon 事务中替换全部数据
并且任一失败不会留下部分恢复
```
