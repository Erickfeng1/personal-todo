# MVP 验收测试

> 文档状态：MVP 基线
> 目的：把需求转为可执行的验收场景
> 级别：Blocker = 发布阻断；Major = 应在 MVP 发布前通过；Minor = 可记录后修复

## 1. 验收环境

- 桌面：至少一个 Chromium 浏览器，并抽测 Safari 或 Firefox。
- 移动端：360px 宽度视口，必要时补充真实手机浏览器。
- 时区：至少测试 `Asia/Shanghai`，日期工具单测覆盖另一个有夏令时的时区。
- 数据集：空库、小数据集、5,000 条压力数据集。
- 离线测试：应用至少成功在线加载一次后切换离线。

## 2. 发布阻断条件

以下任一发生即不能发布：

- 创建或编辑后刷新导致数据丢失。
- Today 错把计划日期当成截止日期，或修改计划日期时清除了截止日期。
- 导入失败后现有数据被部分清除。
- 删除标签导致任务被删除。
- 完成/恢复状态与 Completed 不一致。
- 同一任务可以同时选择“重要”和“不重要”，或同时选择“紧急”和“不紧急”。
- 核心操作在 360px 宽度无法完成。
- 离线状态下本地保存显示成功但实际没有写入。

## 3. 功能验收场景

### AC-001 快速创建普通任务

- 关联需求：MVP-001、MVP-005
- 级别：Blocker

```gherkin
假如 Inbox 为空
当我输入“提交周报”并按 Enter
那么列表立即出现“提交周报”
并且任务处于未完成状态
并且任务位于 Inbox
并且重要性和紧急性均为“未设置”
并且输入框被清空且保持可继续输入
```

### AC-002 拒绝空标题

- 关联需求：MVP-001
- 级别：Major

```gherkin
假如我聚焦快速创建输入框
当我只输入空格并提交
那么系统不创建任务
并且给出可理解的校验提示
```

### AC-003 Today 页面创建任务

- 关联需求：MVP-001、MVP-006
- 级别：Blocker

```gherkin
假如今天是 2026-08-11
当我在 Today 创建“整理会议纪要”
那么任务的计划日期是 2026-08-11
并且任务不在 Inbox
并且显示在“今日计划”分组
```

### AC-004 刷新后保留数据

- 关联需求：MVP-010
- 级别：Blocker

```gherkin
假如我已创建带备注、项目、标签、重要性、紧急性、计划日期和截止日期的任务
当我刷新页面并重新打开任务
那么所有字段与刷新前一致
```

### AC-005 编辑与取消

- 关联需求：MVP-002
- 级别：Major

```gherkin
假如存在任务“初稿”
当我把标题改为“终稿”但选择取消
那么列表仍显示“初稿”
当我再次编辑并保存“终稿”
那么所有相关视图都显示“终稿”
```

### AC-006 计划日期与截止日期独立

- 关联需求：MVP-002、MVP-006
- 级别：Blocker

```gherkin
假如任务计划今天处理且截止日期为本周五
当我把它移出今日计划
那么计划日期被清除或改期
并且截止日期仍为本周五
```

### AC-007 Today 分组与去重

- 关联需求：MVP-006
- 级别：Blocker

```gherkin
假如一项任务既已逾期截止又计划在今天处理
当我打开 Today
那么该任务只显示一次
并且归入“逾期截止”分组
```

### AC-008 未完成计划结转

- 关联需求：MVP-006
- 级别：Major

```gherkin
假如任务计划日期是昨天且仍未完成
当我今天打开 Today
那么任务显示在“未完成结转”分组
并且不被标记为截止逾期，除非它的 deadline 也已过期
```

### AC-009 Upcoming 七天窗口

- 关联需求：MVP-007
- 级别：Major

```gherkin
假如今天是 2026-08-11
并且分别有计划日期为 8 月 12 日、8 月 18 日和 8 月 19 日的任务
并且另有一项任务计划日期为 8 月 12 日、截止日期为 8 月 15 日
当我打开 Upcoming
那么显示前两项
并且不显示 8 月 19 日任务
并且不显示今天的任务
并且同时有计划和截止日期的任务只在 8 月 12 日出现一次，但仍显示 8 月 15 日截止信息
```

### AC-010 完成与撤销

- 关联需求：MVP-003
- 级别：Blocker

```gherkin
假如 Today 中存在未完成任务
当我完成该任务
那么它退出 Today 并进入 Completed
并且记录完成时间
当我点击撤销
那么它恢复为未完成并回到原视图
```

### AC-011 从 Completed 恢复

- 关联需求：MVP-003
- 级别：Major

```gherkin
假如 Completed 中存在一项计划今天的任务
当我选择恢复
那么 completedAt 被清空
并且任务重新出现在 Today
并且项目、标签、重要性、紧急性和日期保持不变
```

### AC-012 删除与撤销

- 关联需求：MVP-004
- 级别：Blocker

```gherkin
假如存在任务“临时任务”
当我删除它
那么它立即从普通视图和搜索中消失
当我点击撤销
那么它恢复到删除前的状态和视图
```

### AC-013 整理 Inbox

- 关联需求：MVP-005、MVP-008
- 级别：Major

```gherkin
假如 Inbox 中存在任务
当我为它选择项目“工作”
那么任务默认退出 Inbox
并且出现在“工作”项目页
```

### AC-014 标签不自动移出 Inbox

- 关联需求：MVP-005、MVP-008
- 级别：Major

```gherkin
假如 Inbox 中存在未整理任务
当我只添加标签“等待回复”
那么任务仍然保留在 Inbox
并且也能从标签页找到
```

### AC-015 项目归档不丢任务

- 关联需求：MVP-008
- 级别：Blocker

```gherkin
假如项目“旧项目”包含活动任务和已完成任务
当我归档该项目
那么项目不再出现在默认项目选择器
并且活动任务仍可在 Today、Upcoming 或搜索中找到
并且已完成任务仍可在 Completed 中找到
```

### AC-016 删除标签不删除任务

- 关联需求：MVP-008
- 级别：Blocker

```gherkin
假如标签“外出”关联 3 项任务
当我删除该标签并确认
那么系统先显示影响数量 3
并且删除后这 3 项任务仍然存在
并且它们不再包含“外出”标签
```

### AC-017 搜索标题和备注

- 关联需求：MVP-009
- 级别：Major

```gherkin
假如任务 A 的标题包含“合同”
并且任务 B 的备注包含“合同”
当我搜索“合同”
那么结果同时包含任务 A 和任务 B
并且不包含软删除任务
```

### AC-018 搜索是否包含已完成

- 关联需求：MVP-009
- 级别：Major

```gherkin
假如一个匹配搜索词的任务已经完成
当“包含已完成”关闭时
那么结果不显示它
当我开启“包含已完成”
那么结果显示它
```

### AC-019 导出完整备份

- 关联需求：MVP-011
- 级别：Blocker

```gherkin
假如数据库含任务、项目、标签和自定义设置
当我执行导出
那么浏览器下载一个 JSON 文件
并且文件包含 schemaVersion、appVersion 和 exportedAt
并且摘要数量与数据库一致
并且每项任务的重要性与紧急性分类被完整导出
```

### AC-020 拒绝无效备份

- 关联需求：MVP-011
- 级别：Blocker

```gherkin
假如现有数据库包含 10 项任务
当我选择格式错误或引用不存在项目的备份文件
那么系统显示校验错误
并且现有 10 项任务保持不变
```

### AC-021 事务性恢复

- 关联需求：MVP-011、NFR-002
- 级别：Blocker

```gherkin
假如我选择一个有效备份并确认替换恢复
当恢复过程中任一表写入失败
那么整个恢复事务回滚
并且恢复前的数据保持完整
```

### AC-022 恢复后实体一致

- 关联需求：MVP-011
- 级别：Blocker

```gherkin
假如我从当前数据库导出备份
并在隔离测试数据库中恢复它
那么任务、项目、标签、设置及其关联与导出前一致
```

### AC-023 离线核心操作

- 关联需求：MVP-010、MVP-013
- 级别：Blocker

```gherkin
假如应用曾成功在线加载
当我切换为离线并重新打开应用
那么应用显示离线提示
并且我仍能创建、编辑、完成和恢复任务
并且重新刷新后这些修改仍存在
```

### AC-024 新版本更新提示

- 关联需求：MVP-013
- 级别：Major

```gherkin
假如 Service Worker 检测到新版本
并且我正在编辑未保存备注
那么应用提示有新版本
并且不会自动刷新丢失草稿
```

### AC-025 键盘快速操作

- 关联需求：MVP-012
- 级别：Major

```gherkin
假如焦点不在输入控件中
当我按 n
那么快速创建输入框获得焦点
当我按 /
那么搜索框获得焦点
当我打开任务详情并按 Esc
那么详情关闭且焦点返回原任务
```

### AC-026 移动端核心流程

- 关联需求：MVP-012
- 级别：Blocker

```gherkin
假如视口宽度为 360px
当我依次创建任务、打开详情、设置日期并完成任务
那么所有操作均可完成
并且页面没有阻断性横向滚动
并且主要按钮可见且可触控
```

### AC-027 存储写入失败

- 关联需求：MVP-010、NFR-007
- 级别：Blocker

```gherkin
假如 IndexedDB 写入被模拟为失败
当我编辑并保存任务
那么系统明确提示保存失败
并且不显示虚假的“已保存”状态
并且表单草稿仍可复制或重试
```

### AC-028 大数据可用性

- 关联需求：NFR-001
- 级别：Major

```gherkin
假如数据库中有 5000 项任务
当我打开 Today 并输入搜索词
那么页面保持可操作
并且输入过程中没有持续明显卡死
```

具体性能阈值由首次基准测试记录，不在没有测量环境时虚构固定毫秒承诺。

### AC-029 设置重要性与紧急性

- 关联需求：MVP-014
- 级别：Blocker

```gherkin
假如存在一项两个维度均未设置的任务
当我把重要性设为“重要”并把紧急性设为“紧急”
那么任务显示“重要”和“紧急”两个系统分类标识
并且该任务属于“重要且紧急”象限
当我把重要性改为“不重要”
那么“重要”被“不重要”替换而不是同时保留
并且该任务改属“不重要但紧急”象限
```

### AC-030 按维度、象限和未分类筛选

- 关联需求：MVP-009、MVP-014
- 级别：Blocker

```gherkin
假如分别存在四个完整象限的任务
并且另有一项只设置为“重要”、紧急性未设置的任务
当我筛选“重要”
那么结果包含“重要且紧急”“重要但不紧急”和只设置“重要”的任务
当我筛选“重要且紧急”象限
那么结果只包含两个维度都精确匹配的任务
当我筛选“未分类”
那么结果包含任一维度未设置的任务
并且不包含四个完整象限的任务
```
