# 个人待办工具竞品研究

> 文档状态：初稿
> 研究日期：2026-08-11
> 研究类型：基于官方产品资料的桌面研究，尚未替代真实上手测试
> 研究目的：提取成熟产品中已经验证的设计原则，为 MVP 范围、交互和数据模型提供依据

## 1. 研究问题

本研究不以复制竞品功能为目标，而是回答以下问题：

1. 哪些个人任务管理交互已经被多款成熟产品反复验证？
2. 哪些能力应该进入本产品 MVP？
3. 哪些能力会显著扩大复杂度，应该延后？
4. 本产品应在哪些体验上形成清晰取舍？
5. 竞品洞察是否要求调整任务的数据模型？

## 2. 研究范围与方法

选择六款不同路线的代表性产品：Todoist、TickTick/滴答清单、Microsoft To Do、Things、Apple 提醒事项、Google Tasks。Notion 作为相邻替代方案，用于观察“高度可配置”与“低操作摩擦”之间的取舍。

本轮比较维度：

- 快速收集任务
- 每日计划
- 计划日期、截止日期和提醒的语义
- 项目、清单、标签和智能视图
- 搜索与导航
- 完成、撤销与归档
- 日历和生态集成
- 数据安全和离线使用
- 功能复杂度

限制：本轮主要依据官方资料，不对市场份额、付费转化或真实留存作判断。开发 MVP 前仍需用同一组任务完成一轮上手实测。

## 3. 竞品洞察

### 3.1 Todoist：快速输入与智能视图

值得借鉴：

- 任务创建入口始终容易到达。
- 一行输入可以逐步承载日期、优先级等信息。
- Today、Upcoming、Priority 让用户在不整理全部任务的情况下也能开始工作。
- 项目表达归属，标签和过滤器表达跨项目场景。

不在 MVP 照搬：

- 复杂过滤语法。
- 团队协作、分派和评论。
- 大量第三方集成。
- 完整自然语言解析器。

对本产品的影响：快速创建只要求标题；搜索和智能视图是核心能力，不是后期装饰。

参考：[Todoist Filters](https://www.todoist.com/help/articles/introduction-to-filters-V98wIH)、[Todoist Plans & Features](https://www.todoist.com/pricing/)

### 3.2 TickTick/滴答清单：任务与时间安排结合

值得借鉴：

- Today、Tomorrow 等智能清单降低整理成本。
- 日历视图帮助用户判断某天是否安排过载。
- 列表和日历只是同一份任务数据的不同呈现。
- 专注、习惯等能力说明任务执行阶段存在扩展空间。

不在 MVP 照搬：

- 习惯、番茄钟、完整可视化艾森豪威尔矩阵、统计同时上线。
- 完整日历订阅和双向同步。
- 多种视图一次性实现。

对本产品的影响：MVP 先提供列表式 Upcoming；日历视图进入后续版本，不能反向绑架任务核心模型。重要性/紧急性采用轻量的两轴分类和筛选，不在 MVP 增加独立矩阵页面、拖拽象限或统计模块。

参考：[TickTick Features](https://www.ticktick.com/features)、[TickTick Calendar](https://help.ticktick.com/articles/7055782166172532736)

### 3.3 Microsoft To Do：My Day 与每日重新承诺

值得借鉴：

- “My Day”强调今天主动选择做什么，而不是简单显示今天到期的任务。
- 每日计划可以重置，未完成任务仍保留并在以后重新出现。
- 默认视图简单，适合个人用户快速理解。

不在 MVP 照搬：

- Outlook 邮件和 Microsoft 365 深度集成。
- 自动建议算法。

对本产品的影响：必须区分“计划哪天做”和“最晚哪天完成”。任务模型采用 `plannedDate` 与 `deadline` 两个字段；Today 同时展示今日计划、截止任务和未完成结转，但要分组而不是混为一谈。

参考：[Microsoft To Do — My Day and suggestions](https://support.microsoft.com/en-US/ToDo/my-day-and-suggestions)

### 3.4 Things：渐进式呈现与时间视图

值得借鉴：

- Inbox、Today、Upcoming、Anytime、Someday 各自有清楚的心智模型。
- 创建任务时保持简单，标签、检查清单、计划日期和截止日期按需展开。
- Quick Find 同时承担查找与导航。
- 已完成内容进入 Logbook，避免完成后无迹可寻。
- 计划日期控制任务何时进入视野，截止日期表达硬约束。

不在 MVP 照搬：

- Apple 平台特有的系统集成。
- 复杂动画和完整拖拽体系。
- Someday、Anytime 等所有高级语义一次上线。

对本产品的影响：默认界面只突出标题、完成状态和关键日期；任务详情使用渐进式披露；已完成任务有独立视图。

参考：[Things Features](https://culturedcode.com/things/features/)、[Things Today, Upcoming, Anytime and Someday](https://culturedcode.com/things/support/articles/4001304/)

### 3.5 Apple 提醒事项：标签与智能列表

值得借鉴：

- 普通列表表达固定归属。
- 标签表达跨列表场景。
- 智能列表根据日期、标签等规则自动聚合，不复制任务。
- 模板和系统入口可明显降低重复录入成本。

不在 MVP 照搬：

- 位置提醒、共享列表和 Apple 系统级入口。
- 购物清单自动分类。
- 自定义智能列表编辑器。

对本产品的影响：一项任务最多属于一个项目，但可以有多个标签；Today、Upcoming、Completed 都是查询视图，不创建任务副本。

参考：[Apple — Organize reminders](https://support.apple.com/en-us/119953)

### 3.6 Google Tasks：入口与生态整合

值得借鉴：

- 用户可以在 Gmail、Calendar 等上下文中快速创建任务。
- 有日期和时间的任务自然进入日历。
- 周期任务需要清楚区分修改单次和修改整个系列。

不在 MVP 照搬：

- Google Workspace 集成。
- 周期任务与子任务组合。
- 日历双向编辑。

对本产品的影响：先做好应用内全局快速创建；周期任务和外部入口延后，避免过早引入系列实例模型。

参考：[Google Tasks Overview](https://support.google.com/tasks/answer/7675772?hl=en)、[Google Tasks — Repeating tasks](https://support.google.com/tasks/answer/12132599?hl=en)

### 3.7 Notion：高度灵活的反向参照

Notion 的数据库可以表达丰富字段和视图，但灵活性也意味着用户可能需要先设计系统，再开始记录任务。本产品不追求成为通用数据库或项目管理平台。

借鉴：字段和视图可扩展。
避免：创建任务前必须选择模板、配置数据库或理解复杂状态。

参考：[Notion Task Databases](https://www.notion.com/help/sprints)

## 4. 横向结论

| 已验证的模式 | 本产品取舍 | MVP 决策 |
|---|---|---|
| 快速收集比字段完整更重要 | 创建时只要求标题 | 纳入 |
| 今日计划不等于今天截止 | 使用 `plannedDate` 与 `deadline` | 纳入 |
| 项目和标签解决不同问题 | 一个项目、多个标签 | 纳入 |
| 重要性与紧急性是两个独立判断 | 两个系统维度组合成四象限 | 纳入轻量分类与筛选 |
| 智能视图不应复制任务 | 由查询动态计算 | 纳入 |
| 字段应渐进式呈现 | 列表简洁，详情完整 | 纳入 |
| 完成后应可查、可撤销 | 完成视图与撤销反馈 | 纳入 |
| 数据所有权影响信任 | 本地优先、可导出恢复 | 纳入 |
| 自然语言能提高速度 | 价值高但实现边界复杂 | 延后 |
| 日历能暴露计划过载 | 先做 Upcoming 列表 | 延后日历 |
| 周期任务很常用 | 系列与实例规则复杂 | 延后 |
| 提醒依赖系统权限和后台能力 | Web 可靠性需要专项验证 | 延后 |
| 习惯、专注、统计可扩展产品 | 容易偏离待办核心 | 不进入近期路线 |

## 5. 产品机会

本产品的推荐定位：

> 一个本地优先、无需登录、打开即用，强调“每日主动计划”而不是堆积截止日期的轻量个人待办工具。

核心差异化不是更多功能，而是：

1. 创建足够快。
2. 今日计划与截止压力分开呈现。
3. 数据默认留在本地，并能随时导出恢复。
4. 无团队协作、无复杂配置、无信息噪音。

## 6. 下一轮上手测试

开发前，用每款产品完成以下统一场景并记录点击次数、理解成本和异常情况：

1. 创建“明天下午 3 点给客户回电话”。
2. 创建一条无日期想法。
3. 把任务安排到今天，但截止日期设为周五。
4. 创建工作、生活两个项目。
5. 给任务添加“等待回复”标签。
6. 找到所有“重要且紧急”的已逾期任务，并单独筛选所有“重要”任务。
7. 完成任务并撤销。
8. 搜索一个月前完成的任务。
9. 创建周期任务并修改其中一次。
10. 尝试导出或备份数据。

实测发现应记录在 [`decision-log.md`](./decision-log.md)，仅在影响范围、数据结构或关键交互时更新其他规格文档。
